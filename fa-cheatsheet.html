Font Awesome 7 离线使用教程

适用于本目录的 Font Awesome Free 7.3.1（web 版）。全部内容离线可用，覆盖：基本用法、CSS/Unicode 写法，以及从 Font Awesome 4 老项目迁移到 7 的完整方案。

一、快速开始

1. 用 VS Code Live Server 打开本页

  1. VS Code 打开 fontawesome-free-7.3.1-web 文件夹；
  2. 安装 Live Server 扩展（第一次需要）；
  3. 右下角点 Go Live（或在 html 文件上右键 → Open with Live Server）；
  4. 浏览器访问 http://127.0.0.1:5500/fa-cheatsheet.html。
本页的数据是预生成的 fa-cheatsheet-data.js（用 <script> 加载，不用 fetch），所以直接双击 html 文件（file:// 方式）也能打开使用。但你的项目页面建议始终走 http（Live Server），更接近真实部署。

2. 在你自己的页面里用图标（只要三行）

<!-- 1. 引入样式（相对路径按你的目录调整，需保证能访问到 css/ 和 webfonts/）-->
<link rel="stylesheet" href="css/all.min.css">

<!-- 2. 使用：风格前缀 + 图标名 -->
<i class="fa-solid fa-house"></i>
<i class="fa-brands fa-github"></i>
webfonts/ 目录必须和 css/ 一起部署：all.min.css 里写的是 url(../webfonts/fa-solid-900.woff2)，按 css 文件的相对位置找字体。只拷 css 不拷 webfonts，图标会显示成方块。
↑ 上面就是本地字体渲染的真实效果

二、目录结构：哪些文件是你需要的

│  ├─ fa-regular-400.woff2
│  ├─ fa-brands-400.woff2
│  └─ fa-v4compatibility.woff2  ← 仅方案 C 用到
├─ js/                     ← SVG+JS 另一种用法（可选，本教程以 CSS 方式为主）
├─ svgs/ · svgs-full/ · sprites/  ← 单个 SVG 文件 / 雪碧图（可选）

本包图标全部免费可用：图标库里的 1992 个图标（含全部品牌 Logo、全部 69 个分类）都是 Free 版内容，可免费商用（图标 CC BY 4.0、字体 SIL OFL 1.1、代码 MIT）。Pro 版的差异在于额外的 light / thin / duotone / sharp 风格和更多图标——免费包的元数据里不含任何付费图标，所以本页搜到的都能放心用，不存在"看到却用不了"的坑。

五、在 CSS / HTML 里直接用 Unicode

方式 1：伪元素 ::before（老项目最常见的自定义写法）

.my-star::before {
  font-family: "Font Awesome 7 Free";  /* 品牌图标用 "Font Awesome 7 Brands" */
  font-weight: 900;                     /* solid=900，regular=400，brands=400 */
  content: "\f005";                    /* 五角星 unicode，本页每个图标都标了 */
}
上面就是这段 CSS 的真实渲染

方式 2：HTML 实体

<span style="font-family:'Font Awesome 7 Free';font-weight:900">&#xf015;</span>

方式 3（FA7 新增）：--fa 变量

FA7 的 CSS 把每个图标的字符放进 --fa 变量，再用统一的 ::before 输出。所以你可以不记类名，直接给变量赋值：

<i class="fa" style="--fa: '\f015'"></i>

/* 或者在自定义类里定义 */
.icon-home { --fa: "\f015"; }
↑ --fa 变量方式渲染的 house

提示：本页点任意图标弹出的详情里，这几种写法都会按该图标自动生成好，复制即可。

六、从 Font Awesome 4 迁移到 7（重点）

6.1 核心差异

项目FA4 老写法FA7 新写法
类名语法fa fa-home（一个 fa 前缀包打天下）fa-solid fa-house（风格前缀 + 图标名，两个类）
空心 / outline 图标加 -o 后缀：fa fa-star-o换成 regular 风格：fa-regular fa-star
品牌图标也是 fa fa-qq用 brands 前缀：fa-brands fa-qq
字体家族名"FontAwesome""Font Awesome 7 Free" / "Font Awesome 7 Brands"
图标重命名fa-search、fa-trash、fa-times…fa-magnifying-glass、fa-trash-can、fa-xmark…（大量改名，别名见附录）
尺寸 / 动画类fa-lg、fa-2x、fa-spin…不变，可直接沿用，还新增了 fa-2xs~2xl、fa-beat 等

Unicode 码位绝大多数没变（f015 还是 house），所以content:"\f015" 这种老 CSS 基本不受影响；受影响的主要是类名。

6.2 先决定：用 v7 整体替换，还是 v4/v7 共存？

结论先行：推荐「v7 整体替换 + v4-shims 过渡」，不建议 v4 和 v7 长期共存。v7 加 shims 已经能覆盖 v4 的全部类名写法，共存只会带来两倍字体下载和排查困难的样式冲突。

你的情况建议做法
老项目只引了 v4 的 CSS（font-awesome.min.css，最常见） 这是官方唯一形态，v4 本来就没有 JS。删掉 font-awesome.min.css 和 fonts/fontawesome-webfont.*，换成 v7 的 all.min.css + webfonts/，再在其后引入 v4-shims.min.css——老代码立即全部恢复显示。之后按方案 A 逐步改类名，改完删掉 shims。
老项目引过 fa 的 JS（v5/v6 的 all.js，或第三方封装的 fa 脚本） v7 对应 js/all.min.js；JS 方式下的 v4 老类名兼容垫片是 js/v4-shims.min.js（放在 all.js 之后）。注意：CSS 字体方式和 JS(SVG) 方式二选一，同一页面不要同时引入，否则图标会被处理两次。拿不准可用包内 js/conflict-detection.js 排查冲突。
过渡期确实想两版同时挂（完全不敢动老页面） 技术上可行：两版字体家族名不同（"FontAwesome" vs "Font Awesome 7 Free"），互不覆盖字体本身。但 .fa 基类两边都定义，后加载的样式表会覆盖先加载的，老图标的渲染会随引入顺序漂移；且两套字体都会被下载。若必须共存：老页面只引 v4、新页面只引 v7（按页面隔离），并设定明确的收尾时间，不要在同一页面混引两版完整 CSS。

6.3 方案 A：逐个替换类名（推荐，一劳永逸）

  1. 在老项目里全局搜索 class="fa fa-，把所有用图标的地方列出来；
  2. 打开本页搜索框，直接输入 v4 旧名（如 home、envelope-o）或旧编码（如 f015）——本页已收录全部 v4 旧名映射，搜旧名就能找到新图标；
  3. 点开图标详情，复制新生成的 <i> 写法替换。
<!-- FA4 老代码 -->
<i class="fa fa-home"></i>        <!-- 改成 → <i class="fa-solid fa-house"></i> -->
<i class="fa fa-search"></i>      <!-- 改成 → <i class="fa-solid fa-magnifying-glass"></i> -->
<i class="fa fa-envelope-o"></i>  <!-- 改成 → <i class="fa-regular fa-envelope"></i> -->
<i class="fa fa-qq"></i>          <!-- 改成 → <i class="fa-brands fa-qq"></i> -->

改完类名后引入 css/all.min.css 即可，不再需要任何 shim 文件。

6.4 方案 B：不改老代码，引入 v4-shims（快速过渡）

如果老代码量大、暂时不想逐个改，FA7 仍然自带 v4 兼容垫片。在 all.min.css 之后引入：

<link rel="stylesheet" href="css/all.min.css">
<link rel="stylesheet" href="css/v4-shims.min.css">

<!-- 老代码原样保留，仍能显示 -->
<i class="fa fa-envelope-o"></i>

原理：v4-shims.css 里是对每个旧类名的补丁规则，例如 .fa.fa-envelope-o { font-family:"Font Awesome 7 Free"; font-weight:400; --fa:"\f0e0"; }，把 v4 命名翻译成 v7 的字体与字符。

  • 适用范围：HTML 里 class="fa fa-xxx" 这种字体方式的老写法；
  • 如果你的老项目用的是 SVG+JS 方式（引入过 js/all.min.js），对应垫片是 js/v4-shims.min.js，在它之后引入即可；
  • shims 只做“旧名 → 新图标”的映射，不能补齐免费版没有的 regular 图标（见下面常见坑）。

6.5 方案 C：老 CSS 里直接写了 "FontAwesome" 字体名 / content 码位

有些老项目在自定义 CSS 里绕过类名直接写字体，例如：

.my-icon::before {
  font-family: "FontAwesome";   ← FA4 的字体名，v7 字体里没有这个名字
  content: "\f041";             ← 个别码位在 v5+ 已让给别的图标
}

这时不用改 CSS，引入字体名兼容层即可：

<link rel="stylesheet" href="css/all.min.css">
<link rel="stylesheet" href="css/v4-font-face.min.css">

它会以 "FontAwesome" 这个老名字注册 4 组 @font-face，按 unicode-range 分流：常规码位 → 新的 solid/regular/brands 字体文件；v4 时代被重新分配的码位（如 f041 地图钉、f09a facebook 等）→ 专门的 fa-v4compatibility.woff2，保证老码位还能显示成老图标。

6.6 常见坑

  • -o 图标显示不出来：免费版 regular 只有 169 个。shims 会把 fa-xxx-o 映射到 regular 风格，若该图标没有 regular 版（如 fa-battery-0 这类本就不是 outline 的），检查样式是否落在 solid 上；实在没有就手动改用 solid。
  • 图标显示为方块：90% 是 webfonts/ 没部署或路径不对。F12 → Network 看字体请求是否 404。
  • 品牌图标不显示：brands 是独立字体，必须用 fa-brands 前缀（或 shims 正确接管）。
  • 改了没生效：浏览器缓存了老 CSS。硬刷新（Cmd+Shift+R）/ 清缓存，Live Server 一般会自动重载。
  • 个别 v4 图标在 v7 搜不到：极少数被合并或改名后没进别名表。用附录总表按旧名查一遍，或到 metadata/shims.json 里确认。
  • 不用改的部分：fa-lg / fa-2x / fa-fw / fa-spin / fa-rotate-90 等工具类名称全部沿用； brands 图标名大多也没变。

6.7 迁移检查清单

  • 全局搜索 fa fa-，列出所有图标使用点
  • 逐个用本页搜索旧名，确认新类名（regular 缺失时改用 solid）
  • 检查 CSS 里是否硬编码了 font-family:"FontAwesome" 或旧码位 → 决定是否需要方案 C
  • 部署 css/ + webfonts/，确认相对路径能访问（Network 无 404）
  • 过不去的老代码先挂 v4-shims.min.css，排期后再走方案 A
  • 删掉 v4 时代的 fontawesome.css / fontawesome-webfont.* 老文件，避免新旧混用

七、部署到实际项目

7.1 要拷贝哪些文件

最小集合只有两样：一个 CSS 文件 + 整个 webfonts 目录。

your-project/
└─ assets/
   └─ fontawesome/              ← 建议独立成目录，升级时整体替换
      ├─ css/
      │  └─ all.min.css         ← 唯一必需的 CSS（三种风格全包含）
      └─ webfonts/              ← 整个目录原样拷贝（4 个 woff2，共约 300KB）
         ├─ fa-solid-900.woff2
         ├─ fa-regular-400.woff2
         ├─ fa-brands-400.woff2
         └─ fa-v4compatibility.woff2   ← 仅方案 C 用到，一并带上也不亏
  • 按需可选：css/v4-shims.min.css（v4 老类名过渡）、css/v4-font-face.min.css（老字体名兼容）；
  • 其余内容——js/、scss/、sprites/、svgs/、metadata/ 以及本页三件套——都不需要发布；
  • 目录名不要求叫 fontawesome，放 assets/lib/、static/vendors/ 都行，关键是下面这条。
css/ 和 webfonts/ 必须保持「兄弟目录」的相对位置：CSS 内部写死了 url(../webfonts/…)，是从 CSS 文件自身位置去解析的。两个目录整体搬到哪里都能用；但把 webfonts 合并进 css/、或拆到别处，字体就会 404，图标全变方块。

7.2 纯 HTML / 多页网站

在每个用到图标的页面 <head> 里引入（路径按你的目录层级调整）：

<!-- 推荐根绝对路径（以 / 开头），页面换层级不容易断 -->
<link rel="stylesheet" href="/assets/fontawesome/css/all.min.css">

<!-- 页面里直接用 -->
<i class="fa-solid fa-house"></i>

如果站点部署在子路径下（比如内网 http://内网IP/app/），根路径会失效，改用相对路径：href="assets/fontawesome/css/all.min.css"（相对当前页面），并注意多级目录页面要补 ../。

7.3 前端工程（Vite / Vue / React / webpack）

方式一（推荐）：npm 安装。版本交给包管理器，打包器会自动把 CSS 里的字体文件复制进产物并改写路径，完全不用操心 webfonts：

npm install @fortawesome/fontawesome-free
// 入口文件顶部（main.js / main.ts / index.js），全项目引一次即可
import '@fortawesome/fontawesome-free/css/all.min.css';

方式二：拷贝到静态目录（Vite 的 public/、webpack 的 static/），和 7.1 的结构完全一样：

your-project/
└─ public/
   └─ fontawesome/
      ├─ css/all.min.css
      └─ webfonts/*.woff2

<!-- index.html 里（public 下的内容发布后在站点根）-->
<link rel="stylesheet" href="/fontawesome/css/all.min.css">
  • Vue / React 组件里直接写 <i class="fa-solid fa-user"></i> 即可，就是普通标签，不需要注册任何组件；
  • 两种方式选一种，不要 npm 装一份、public 又拷一份，容易出现版本漂移；
  • 如果项目对体积敏感：可以改用 svgs/ 目录里的单个 SVG 内联，或用 fonttools 按用到的码位给 woff2 瘦身（见第八章）。

7.4 部署后不显示？按这个查

现象原因与处理
字体 404（Network 里 woff2 标红）webfonts 目录没拷 / 被构建规则排除 / 与 css 的相对位置不对。对照 7.1 修复目录结构。
本地好的，上线变方块服务器对 .woff2 的 MIME / 缓存策略问题，或打包工具没把字体文件带进产物（检查构建配置的 assets 规则）。
改路径后部分页面好部分坏绝对/相对路径混用。统一成一种，多页站优先根绝对路径。
要升级 FA 版本下载新版包，整体替换 fontawesome 目录；再重跑 fa-cheatsheet-build.py 更新本页数据。

八、常见问题排查
